# سامانه جامع مدیریت عملکرد اصفهان چالاک

نسخه ۲.۱ یک برنامه React/TypeScript با رابط فارسی و راست‌به‌چپ است که برای Cloudflare Pages Functions و Workers KV آماده شده است. حوزه‌های اصلی آن شامل کارکنان و ساختار سازمانی، بانک شاخص و پروفایل شغلی، ارزیابی و کالیبراسیون، گردش کار، گزارش و ماتریس ۹ خانه، پاداش، OKR، جلسات یک‌به‌یک، بهره‌وری، پشتیبانی و تحلیل‌های Gemini است.

## معماری

- `src/`: رابط React، منطق دامنه، اعتبارسنجی، ورود/خروجی Excel و ذخیره‌سازی offline-first
- `functions/api/`: APIهای Cloudflare، نشست امن، همگام‌سازی نقش‌محور و پراکسی Gemini
- `cloudflare/`: ابزارهای مشترک احراز هویت و رمزنگاری برای Functions
- `public/`: هدرهای امنیتی، مسیرهای Functions و منابع ایستا

نسخه Cloudflare از نشست تصادفی ذخیره‌شده در KV و کوکی `HttpOnly + Secure + SameSite=Strict` استفاده می‌کند. کلمه‌های عبور با PBKDF2/SHA-256 هش می‌شوند و در پاسخ state یا payload همگام‌سازی نگهداری نمی‌شوند. مدیر به کل state دسترسی دارد؛ سرپرست فقط ارزیابی خود و زیرمجموعه‌اش و کارمند فقط ارزیابی خودش را می‌تواند در API تغییر دهد.

همگام‌سازی پس از ورود فعال می‌شود، تغییرها را به‌صورت کلیدهای مستقل می‌فرستد و با شمارهٔ بازبینی سرور دریافت می‌کند. بنابراین یک مرورگر قدیمی نمی‌تواند با ارسال یک نسخهٔ کامل و کهنه، بخش‌های نامرتبط ثبت‌شده در مرورگر دیگر را پاک کند. تغییرهای رسیده از ابر نیز در رابط فعال اعمال می‌شوند و وضعیت واقعی «در حال همگام‌سازی»، «ذخیره‌شده در ابر» یا «خطای فضای ابری» در سربرگ دیده می‌شود.

## اجرای محلی رابط

```bash
npm ci
npm run dev
```

این حالت برای توسعه سریع رابط است و در نبود Pages Functions از داده و ورود آزمایشی مرورگر استفاده می‌کند. برای آزمون کل پشته Cloudflare:

```bash
copy .env.example .dev.vars
# مقدارهای واقعی ADMIN_PASSWORD و GEMINI_API_KEY را در .dev.vars قرار دهید
npm run cf:dev
```

سپس آدرس چاپ‌شده توسط Wrangler را باز کنید. ورود اولیه مدیر با نام کاربری `admin` و مقدار `ADMIN_PASSWORD` انجام می‌شود. پس از اولین ورود مدیر، داده پایه در KV راه‌اندازی می‌شود؛ رمز اولیه کاربر جدید کد پرسنلی اوست و باید از مرکز مدیریت تغییر کند.

## کنترل کیفیت

```bash
npm run check
npm run cf:functions
npm audit
```

`check` به ترتیب type-check، تست و build تولیدی را اجرا می‌کند.

## استقرار Cloudflare Pages

1. یک Pages project و یک Workers KV namespace بسازید.
2. binding با نام دقیق `CHALAK_DB` را به KV متصل کنید. شناسه namespace فعلی در `wrangler.jsonc` ثبت شده است؛ اگر حساب یا namespace عوض شد، همان شناسه را جایگزین کنید.
3. secrets را تنظیم کنید (آن‌ها را داخل Git یا `wrangler.jsonc` قرار ندهید):

```bash
npx wrangler pages secret put ADMIN_PASSWORD --project-name chalak-performance
npx wrangler pages secret put GEMINI_API_KEY --project-name chalak-performance
```

4. استقرار را اجرا کنید:

```bash
npm run deploy
```

برای اتصال Git در داشبورد Cloudflare، build command برابر `npm run build` و output directory برابر `dist` است. پس از افزودن یا تغییر binding/secret باید deployment تازه انجام شود.

### کنترل اتصال فضای ابری

پس از استقرار، در حالت خارج‌شده از حساب آدرس زیر باید پاسخ JSON بدهد:

```text
https://YOUR-DOMAIN/api/health
```

مقدار `storage` باید `workers-kv` و `configured` باید `true` باشد. اگر وضعیت 503 یا `configured: false` دیده شد، binding با نام دقیق `CHALAK_DB` در همان Pages project وجود ندارد یا deployment پس از افزودن binding دوباره اجرا نشده است.

برای کنترل بین دو مرورگر، با یک حساب در هر دو وارد شوید، در مرورگر اول یک رکورد آزمایشی بسازید و چند ثانیه بعد وضعیت آن را در مرورگر دوم بررسی کنید. نشان سربرگ باید ذخیره در ابر را تأیید کند. اگر نشان خطا شد، پاسخ `/api/health` و تنظیمات binding را بررسی کنید.

### مدیریت رمزها و نشست‌ها

- رمز اختصاصی کاربر از مرکز مدیریت قابل تنظیم، تولید و بازنشانی به کد پرسنلی است.
- تغییر نام کاربری، اعتبارنامهٔ ذخیره‌شده را به نام تازه منتقل می‌کند.
- تغییر یا بازنشانی رمز، همهٔ نشست‌های قبلی همان حساب را در مرورگرهای دیگر باطل می‌کند.
- تغییر رمز مدیر، نشست فعلی و سایر نشست‌های مدیر را می‌بندد و ورود دوباره با رمز تازه لازم است.
- پاسخ نامعتبر یا HTML از سرور دیگر باعث خطای خام جاوااسکریپت نمی‌شود و پیام قابل‌فهم نمایش داده می‌شود.

### پوشش ویرایش و حذف مدیر

مدیر برای داده‌های اصلی و تنظیمات قابل‌مدیریت، شامل کارکنان، شاخص‌ها، پروفایل‌ها، ارزیابی‌ها، گردش کار، اهداف و نتایج کلیدی، جلسات ۱به۱، تمجید، پاداش، بهره‌وری، رویدادهای تقویم، تیکت‌ها و پاسخ‌های آن‌ها، کنترل ویرایش/حذف دارد. حذف حساب مدیر اصلی عمداً مجاز نیست.

## نکات عملیاتی

- برنامه را فقط روی HTTPS منتشر کنید؛ کوکی production عمداً `Secure` است.
- `ADMIN_PASSWORD` حداقل ۱۲ نویسه تصادفی داشته باشد و دوره‌ای تعویض شود.
- KV برای این نسخه و حجم سازمان کوچک/متوسط مناسب است، ولی همگام‌سازی آن transaction کامل نیست. برای حجم زیاد یا گزارش‌های رابطه‌ای، مهاجرت state به D1 گام بعدی معماری است.
- خروجی‌های JSON/Excel حاوی داده منابع انسانی‌اند؛ سیاست نگهداری و دسترسی سازمان باید روی آن‌ها اعمال شود.
